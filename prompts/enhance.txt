2. FIX MEDICAL RAG QUERY GENERATION
==================================================

Current behavior appears to send an overly broad/full patient narrative into Medical Knowledge RAG.

Change this so the medical retrieval query is a concise clinical-information retrieval query derived from the PatientState.

The query should prioritize:

- chief/current symptoms
- important associated symptoms
- relevant antecedents/history
- clinically meaningful symptom combinations
- age/sex when useful
- important red-flag context

Do NOT include:
- DDXPlus pathology labels
- differential diagnosis labels
- hidden evaluation labels
- retrieval metadata
- patient identifiers
- unnecessary narrative text

Example for a case containing chest pain + dyspnea + palpitations + sweating:

Instead of searching with the entire patient narrative, produce focused retrieval concepts such as:

"pediatric chest pain dyspnea palpitations sweating differential causes red flags"

Potentially use multiple focused queries if the current architecture supports it, for example:

1. symptom cluster query
2. relevant history/context query
3. safety/red-flag query

Do not hard-code the example above. Generate queries programmatically from PatientState.

3. CHANGE MEDICAL RAG RETRIEVAL FROM TOP-K=1
==================================================

Change the relevant Phase 6/demo medical retrieval path from top_k=1 to approximately top_k=5.

Then add relevance filtering.

IMPORTANT:
Do NOT simply pass all 5 results to the Diagnostic Agent.

For each retrieved medical chunk:

- preserve its similarity score
- apply a clearly defined relevance rule
- discard obviously irrelevant evidence
- retain the strongest clinically relevant evidence
- preserve source/title/chunk identity
- keep deterministic behavior

Do not interpret embedding similarity as diagnostic probability.

If all retrieved chunks are below the relevance threshold, the system should explicitly mark medical retrieval as insufficient/irrelevant rather than pretending evidence exists.

Choose the threshold based on the existing retrieval implementation and tests. Do not invent a threshold without inspecting score distributions. If a fixed threshold is inappropriate, implement a conservative relative/absolute relevance policy.

Document the rationale.

5. MODIFY THE DIAGNOSTIC AGENT CONTRACT
==================================================

The current behavior is too conservative when Medical RAG is weak.

Change the Diagnostic Agent rules to:

CASE A — Strong relevant evidence:
- produce a cautious differential
- cite supporting evidence
- distinguish evidence from inference
- express uncertainty

CASE B — Patient information is clinically meaningful but Medical RAG is weak/irrelevant:
- the agent MAY produce a cautious, explicitly uncertain differential based on patient facts and clinical reasoning
- hypotheses must NOT be presented as confirmed diagnoses
- every hypothesis must clearly indicate uncertainty
- identify what information is missing
- distinguish patient facts from model inference
- do not use irrelevant RAG evidence as support
- do not fabricate medical evidence

CASE C — Patient information is genuinely insufficient:
- abstain
- explain why
- list the critical missing information

The key change is:

WEAK/IRRELEVANT RAG ≠ AUTOMATIC ABSTENTION

But:

INSUFFICIENT PATIENT INFORMATION = ABSTENTION

The Diagnostic Agent must never invent evidence merely to avoid abstaining.
