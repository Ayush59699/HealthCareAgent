Create a SIMPLE, LOCAL WHO Fact Sheet crawler for the healthcare-agentic-ai project.

GOAL

Build a small crawler that starts from:

https://www.who.int/news-room/fact-sheets

and discovers the WHO fact-sheet detail pages, whose URLs follow the pattern:

https://www.who.int/news-room/fact-sheets/detail/<topic>

Examples:

https://www.who.int/news-room/fact-sheets/detail/abuse-of-older-people
https://www.who.int/news-room/fact-sheets/detail/abortion

The crawler should collect the available WHO fact sheets across the A–Z catalogue.

IMPORTANT DESIGN DECISION

Do NOT use:

* embeddings
* vector databases
* Qdrant
* FAISS
* RAG
* LLMs
* rerankers
* agents
* diagnosis
* semantic search

This is ONLY a data collection and organization utility.

The future runtime will simply:
patient/query
→ identify a medical topic
→ locate the corresponding WHO text file
→ load relevant text
→ provide that text to the Diagnostic LLM.

For now, ONLY build the crawler and local knowledge files.

IMPLEMENTATION

Use simple Python libraries:

* requests
* BeautifulSoup
* pathlib
* json or csv only if needed for the URL index

Do NOT introduce Selenium, Playwright, Scrapy, LangChain, LlamaIndex, or another large framework.

SOURCE DISCOVERY

1. Request the WHO fact-sheet index page.
2. Parse all links.
3. Keep only links matching:

https://www.who.int/news-room/fact-sheets/detail/<topic>

4. Remove duplicate URLs.
5. Normalize URLs.
6. Sort them alphabetically by topic.
7. Save the discovered URL list locally.

Do NOT guess URLs from A–Z words. Discover the actual links from the WHO index page.

CRAWLING

For every discovered fact-sheet URL:

1. Download the HTML with requests.
2. Use a reasonable User-Agent.
3. Use a timeout.
4. Handle HTTP errors gracefully.
5. Do not crash the entire crawl because one page fails.
6. Add a small delay between requests so the crawler is polite to WHO.
7. Do not crawl unrelated WHO pages.
8. Do not recursively crawl the entire WHO website.

CONTENT EXTRACTION

Extract the MAIN fact-sheet article content only.

Remove:

* navigation
* menus
* header
* footer
* cookie banners
* unrelated links
* advertisements
* social/share controls
* website boilerplate

Preserve the actual medical content.

MOST IMPORTANT:
Preserve the original section structure.

For example, if the WHO page contains:

Key facts
Overview
Symptoms
Causes
Risk factors
Prevention
Treatment

the saved text should retain those headings and the text belonging to each heading.

DO NOT summarize the content.

DO NOT rewrite the medical content.

DO NOT ask an LLM to clean or interpret it.

The crawler should preserve the WHO wording as closely as practical after HTML cleanup.

OUTPUT

Create a simple directory such as:

data/who_fact_sheets/

Inside it, save one `.txt` file per fact sheet:

data/who_fact_sheets/
abuse-of-older-people.txt
abortion.txt
anaemia.txt
asthma.txt
...

Each text file should have a small metadata header such as:

WHO FACT SHEET
Title: Anaemia
URL: https://www.who.int/news-room/fact-sheets/detail/anaemia
Retrieved: <date>

========================================
Key facts
=========

<original WHO text>

========================================
Overview
========

<original WHO text>

etc.

Do NOT remove the medical text just because it is long.

STORE THE WHOLE CLEANED FACT SHEET.

Also create:

data/who_fact_sheets/index.json

containing only lightweight lookup metadata, for example:

[
{
"topic": "anaemia",
"title": "Anaemia",
"url": "https://www.who.int/news-room/fact-sheets/detail/anaemia",
"file": "anaemia.txt"
}
]

The index is NOT a medical knowledge database. It is simply a map from topic → text file.

CRAWL REPORT

Create a small report after crawling containing:

* total URLs discovered
* successful downloads
* failed downloads
* skipped/duplicate URLs
* output directory
* list of failed URLs
* crawl timestamp

Save it as:

data/who_fact_sheets/crawl_report.json

RE-RUN SAFETY

The crawler must be safely rerunnable.

If a text file already exists:

* do not unnecessarily download it again unless --force is specified.

Provide simple command-line options:

python scripts/crawl_who_fact_sheets.py

and optionally:

python scripts/crawl_who_fact_sheets.py --force

Also provide:

python scripts/crawl_who_fact_sheets.py --limit 10

for testing before performing the complete crawl.

TESTING

Before crawling the entire catalogue:

1. Run with --limit 5.
2. Inspect the generated `.txt` files.
3. Verify:

   * title is correct
   * URL is correct
   * medical text is present
   * section headings are preserved
   * navigation/footer junk is not dominating the file
4. Verify index.json points to the correct files.
5. Verify failed pages do not crash the crawler.

Add a small test suite for:

* URL filtering
* URL normalization
* filename generation
* duplicate removal
* extraction fallback
* index generation

MEMORY / MACHINE SAFETY

This must be lightweight for a 16 GB RAM laptop.

IMPORTANT:

* Process pages ONE AT A TIME.
* Do not store all HTML pages in memory.
* Do not load all text files into memory.
* Do not create embeddings.
* Do not start any model.
* Do not use multiprocessing.
* Do not download large unnecessary assets such as images, videos, CSS, or JavaScript.
* Release page content after processing.
* Use reasonable request timeouts.

PROJECT SAFETY

Before implementing, inspect the existing project structure and avoid modifying existing healthcare production components.

Do NOT modify:

* AMG
* existing medical retrieval
* Patient RAG
* Diagnostic Agent
* Grounding
* Clinical Critic
* Safety
* Phase 6 orchestration
* existing indexes
* existing medical corpus

This crawler is an independent knowledge-ingestion utility.

Do not integrate WHO into the live diagnostic pipeline yet.

FINAL REPORT

After implementation, report:

1. Files created/modified.
2. Number of WHO fact-sheet URLs discovered.
3. Number successfully downloaded.
4. Number failed.
5. Example generated files.
6. Whether section structure was preserved.
7. Tests passed.
8. Exact command to perform the full crawl.
9. Confirm that no existing production healthcare/RAG components were changed.

STOP after completing the crawler and validation.

Do NOT proceed to integrating WHO into diagnosis.
