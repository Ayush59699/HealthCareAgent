# Task 6 continued: reference correctness before corpus growth

## Current phase and scope

The project is a Phase 6 research prototype: label-free synthetic DDXPlus patient
structuring, separate patient/medical RAG, diagnostic hypotheses, independent
critic review, and fail-closed output-safety routing. The medical index contains
3,332 chunks. The supplied run exposed reference-existence versus reference-meaning
errors and weak top-five retrieval, not a reason to relax safety or expand again.

This implementation preserves Phase 4/5 prompts and behavior, the Phase 6 state
machine, revision/request budgets, critic instructions, safety decision policy,
patient top-k 1, and live medical candidate top-k 5. No index rebuild, corpus
expansion, new model download, or live cloud generation was performed.

## A. Exact diagnostic references and a bounded consistency gate

The enhanced Phase 6 Diagnostic Agent now receives `PATIENT_EVIDENCE_INVENTORY`:
every ID is paired with its exact fact, decoded question/meaning, and literal
answer. Null demographics, repeated facts, original order and ordinal answers are
preserved. Meanings are copied, not generated by a model or inferred from an index.
The critic receives the same additional inventory without changing its instructions.

The versioned diagnostic prompt (`phase6-diagnostic-inference-v2-exact-references`)
requires copying ID/meaning pairs, atomic observation clauses, per-claim citations,
explicit missingness and no interpretation of undefined numeric scales.

`orchestration/phase6/reference_entailment.py` implements
`patient-reference-consistency-v1`:

- It inspects rationale, supporting and contradicting claims in primary and
  differential hypotheses, after the existing reference-existence checks.
- Recognized simple observations (e.g. dyspnea, choking, palpitations, tingling)
  must occur in **that claim's cited patient facts**, not elsewhere in the output.
  Simple positive/negative/unknown polarity is checked. Numeric answers do not
  become affirmative symptoms or severities.
- Dyspnea + tingling citing symptoms 11/15 (onset/palpitations) fails; citing
  symptoms 12/16 succeeds in the regression fixture. Reordering facts invalidates
  formerly correct IDs rather than changing their meanings implicitly.
- Safe machine-only errors enter the existing bounded provider repair loop.
  Rejected prose is not included in repair instructions or logs. Repairs regenerate
  the complete object against the same evidence inventory; references are never
  silently rewritten by the application.
- The same gate is enforced through the existing application grounding contract,
  including when a provider ignores its validation callback. Exhausted repairs
  withhold output before critic/safety calls. Valid output still requires both.
- Reports record the actual diagnostic/check versions and per-version derived
  audits. The demo displays a **recomputed bounded audit**, separate from the
  original grounding result, with detailed checks in detailed mode.

### Explicit limitations

This is **not a general semantic entailment classifier**. It recognizes a small,
versioned clinical-observation vocabulary and simple clauses. Complex modal or
negated language, unknown terminology, medical-only claims, temporal scope,
laterality, severity, causal reasoning, clinical ranking and external-source
entailment remain unassessed by this checker. Ambiguous language can evade its
coverage; synonyms and negation outside its grammar can produce false positives
or negatives. It cannot guarantee that every extra reference in a multi-reference
claim supports that claim. Its success status deliberately says
`no_mismatch_in_checked_observations`, never "clinically supported". Audits expose
unassessed clauses/claims. The independent critic and unchanged safety validator
remain mandatory, and no medical support is manufactured to satisfy them.

The original enhanced library opt-in remains `enhanced_medical=True`; the
Phase 6 CLI/demo already use this path. No new workflow stage or routing edge was
introduced: existence and bounded consistency are successive checks within the
mandatory grounding gate.

## B. Reproducible local candidate-depth evaluation

From the parent workspace:

```text
uv run python healthcare-agentic-ai/scripts/evaluate_medical_retrieval.py --sample 2 --topic Panic --topic Asthma --topic Hyperventilation --compare-symptom-query
```

The command:

1. Opens the existing medical index with cached BGE embeddings; refuses a missing
   manifest or empty collection. It does not load credentials or call an LLM.
2. Loads validation features with `include_labels=False` and constructs an exact
   PatientState copy solely for this retrieval-only experiment.
3. Runs the same query independently at candidate depths 5, 10, 20 and 50.
4. Records original rank, chunk ID, source/provenance, full text, cosine score,
   filter disposition and title-probe ranks. User-selected title probes never
   enter the retrieval query and are not evaluation labels or ground truth.
5. Separately catalogs matching indexed titles, distinguishing absent topic
   titles from failure to retrieve an existing topic. A missing title does not
   prove that a concept is absent from all passage bodies.
6. Optionally repeats the experiment using symptom-only query formulation.
7. Writes a fresh JSON report with index count, embedding signature and manifest
   checksum. Existing reports are not overwritten. Live retrieval is unchanged.

Options: `--data-dir`, `--storage-path`, `--depths 5 10 20 50`, repeatable `--topic`,
`--report new-path.json`. Keep other local Qdrant users closed during the probe.

## C. Experimental filtering/reranking, not a live policy change

`rag/retrieval_experiment.py` exposes a separate prototype:

```text
BGE candidates -> existing concept filter -> lexical reranker -> at most five
```

The inspectable score is `3 * symptom-title matches + 2 * symptom-body matches +
history-title matches`, with original cosine and chunk ID as deterministic
tiebreakers. It preserves payloads and original scores. This is **not a learned
cross-encoder**, a calibrated relevance score, or proof of clinical support.

For the current-query top 50, the experimental top five were Blood Clots, Sudden
Cardiac Arrest, Asthma in Children, Breast Diseases and Heart Disease in Women.
Asthma moves into the experimental shortlist; obviously this does not establish
which passages are appropriate or which diagnosis is correct. The symptom-only
variant instead ranks Chest Pain, Blood Clots, Heart Attack, Endocarditis and
Sudden Cardiac Arrest. The lexical heuristic can reward misleading overlap and
is deliberately **not wired into the Diagnostic Agent's retrieval**.

Next research step: assess a broader label-free query set with independently
reviewed passage relevance, compare targeted symptom-cluster queries/hybrid
retrieval and a separately evaluated reranker. Existing Panic Disorder coverage
not reaching top 50 warrants query/embedding study. Do not promote a reranker or
expand into thousands of PMC documents based on this one case.
